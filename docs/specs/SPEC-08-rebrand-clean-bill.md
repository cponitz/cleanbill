# SPEC-08 — Rebrand to Clean Bill (brand, copy, claim codes, domain, infrastructure names, design system)

*Status: approved (B-19, 2026-09-16; Part C added 2026-09-17) · Priority **P0 — immediate and exclusive**: no other development (SPEC-03, Resend, Lob, cut-over) starts until SPEC-08 and SPEC-09 are complete (plan v3.2 §3) · Owner: Claude Code (Parts A, B2, B3, C), Charlie (Part B1, domain) · Related: B-09 and B-12 (superseded), O-13, SPEC-07, SPEC-09, ADR 0008, ADR 0012, ADR 0018 · Glossary at the end.*

## Problem

The company is **Clean Bill** (Clean Bill Co., cleanbillco.com). The customer-facing app already says so (SPEC-07 set the `BRAND` and `SUPPORT_EMAIL` tokens on 2026-09-16), but everything else still says Texas Refund Desk: the compliance copy, the letters, the service agreement, the Form 50-114 audit page, the e-mail drafts, the static `docs/` pages, the ops page, the repository docs, and every infrastructure name (GitHub repo, Vercel project, Supabase display name, Mac folder, Python package `trd`, claim-code prefix `TRD-`). Two brands in one product is a trust defect for a company whose pitch is "careful people"; and the letters, the QR code base URL and the claim-code prefix become expensive to change the moment 1,000 pieces are at Lob (Oct 5). Do it now, in one pass, while nothing has been printed or sent.

## Decision (B-19, recorded in `claude/decisions.md`)

One name everywhere: **Clean Bill** to customers; slug **`cleanbill`** for the GitHub repository, the Vercel project, the Supabase display name, the Mac folder and the Python package; claim codes **`CB-XXXX-XXXX`**; domain **cleanbillco.com** with `hello@cleanbillco.com`; texasrefunddesk.com kept and permanently redirected. "Texas Refund Desk" is retired as a name, including as a product name — the launch product is "homestead refunds" from Clean Bill. Supersedes B-09 and B-12. The Supabase project ref `letrfpwskjbgnyacesgv` never changes.

## Rules

1. **Copy files are compliance-reviewed.** In `copy/*.md` change only the brand name, the support e-mail and the domain. Every other word stays until Charlie's copy review (M8) lands; list every changed sentence in the PR description.
2. **The legal footer names the company.** The §41.0051 block and the service agreement "Parties" line say "Clean Bill Co., a private company in Austin, Texas" until the LLC is formed (O-06); when the entity name differs, that is a copy change under rule 1, not a rebrand change.
3. **History stays.** `CHANGELOG.md` entries, ADRs and `docs/specs/SPEC-01…07` keep their original wording; add a one-line "renamed by SPEC-08" note to the ADR index and CHANGELOG. `grep` acceptance below excludes those files.
4. **Nothing else changes in the same PR.** No layout, no logic, no wording beyond the name — so the diff is reviewable in one sitting and CI proves nothing broke.
5. **Ref and secrets never change.** Supabase ref `letrfpwskjbgnyacesgv`, the service-role key, the ops password, GitHub secrets — untouched.

## Part C — the Clean Bill design system (branch `design-system`, after Part A merges)

### Why a design system, and why now
Three surfaces carry the brand and none of them share a definition: the web app (SPEC-07 tokens in `apps/web/src/app/globals.css` — DM Sans, teal/navy, a component sheet), the letters and Form 50-114 packet (reportlab and pdf-lib with their own hard-coded colours and fonts), and the e-mails the agent drafts (plain text today; Resend HTML in Task 4). SPEC-09's `/ops` page is about to add a fourth. A design system makes the brand one definition that every surface imports, so the palette decision (O-13) becomes a one-line change instead of a hunt, and the Sep 26 design review can be run against a single page that shows everything.

### What "design system" means here (all AI; no design tool, no external designer)
The system is **tokens + themes + a component sheet + assets + a living style guide + a written guide + a lint**, in the repo, versioned with the code.

**C1 Tokens — one source of truth.** Move the `:root` primitives and the `--color-*` semantic layer out of `globals.css` into `apps/web/src/styles/tokens.css` (primitives: colour, type family and scale, spacing scale 4/8/12/16/24/32/48/64, radii, shadows, motion durations, breakpoints; semantics: `--color-bg`, `--color-surface`, `--color-ink`, `--color-body`, `--color-muted`, `--color-primary`, `--color-primary-strong`, `--color-primary-tint`, `--color-accent`, `--color-line`, `--color-hairline`, `--color-row-tint`, `--color-success[-bg]`, `--color-error[-bg]`, `--color-disabled`, `--shadow-*`, `--ring`). Every component class in `globals.css` reads semantics only; no primitive and no hex literal outside the tokens files. Tailwind's theme reads the same variables.

**C2 Themes — O-13 without a blocker.** Two primitive palettes as theme files: `theme-handoff.css` (the SPEC-07 teal/navy set exactly as built — the default) and `theme-brief.css` (the Sep 16 brand brief: ground `#FFFFFF`, panel `#F3F6F4`, ink `#12261F`, primary forest `#1E5B45`, accent amber `#C9922E`, rule `#D7DED9`). A theme may also carry its type pairing: the handoff theme keeps DM Sans; the brief theme loads the brief's pairing (Source Serif 4 for headings, Inter Tight for body and UI, both via `next/font`, tabular figures on every dollar amount) so the toggle shows the whole proposal, not only the colours. A theme is selected by one import in `layout.tsx` (`data-theme` attribute honoured for the style-guide toggle). Both themes must pass the contrast rule in C7. Charlie decides O-13 by looking at `/design-system?theme=brief` against the default before Sep 26; switching is a one-line PR.

**C3 Component sheet.** Keep the SPEC-07 classes (`.btn`, `.input`, `.choice`, `.card`, `.pill`, `.progress`, `.nav`, `.footer`, `.acc`, `.flow-*`) and add what SPEC-09 needs (`.table`, `.kpi`, `.badge` by status, `.toolbar`, `.drawer`), each with every state (default, hover, focus-visible, disabled, error, loading) and a documented anatomy. Status colours for claim states come from one map in `src/lib/status.ts`, rendered through tokens.

**C4 Brand assets.** `apps/web/public/brand/`: wordmark SVG (the words "Clean Bill" set in DM Sans, plus a simple original line-drawn mark — a bill/receipt outline with a check, per the brief §10; no stock imagery, no house, no piggy bank), mark-only SVG, favicon (`.svg` + `.ico` + apple-touch), Open Graph image 1200×630 rendered from the tokens, e-mail header PNG (600 px). `layout.tsx` metadata points at them. Photo slots stay the hatched placeholder until photography exists.

**C5 Print and e-mail adapters.** `cleanbill/brand.py` (Python constants generated from `tokens.css` by `python -m cleanbill.brand --sync`, CI-checked for staleness like `findings.ts`): colours, font files (DM Sans TTF vendored under `cleanbill/fonts/` with its OFL licence; Liberation Serif for the §41.0051 block if a serif is kept), wordmark path. `trd/letters/generate.py`, `trd/agent/packet.py`, `trd/agent/form50114.py` and `supabase/functions/process-claim/form50114.ts` (audit page) read from it — letters, the packet data sheet and the audit page carry the wordmark and the palette. `cleanbill/email/base.html`: a table-based, inline-styled e-mail template (header with the wordmark, body, footer with the §41.0051 line and the support address) that Task 4's Resend send wraps every message in; text alternative generated from the same body.

**C6 Living style guide.** Route `/design-system` in `apps/web` (`robots: noindex`, no nav link): every token as a swatch or specimen with its name and value, the type ramp, spacing scale, every component in every state, the status badge map, the wordmark and mark on light and dark, the e-mail template rendered in an iframe, and a theme toggle (handoff / brief). This page is what the Sep 26 design review looks at.

**C7 Written guide and rules.** `docs/DESIGN-SYSTEM.md`: principles (from the brand brief §3, §6, §10 — prudent, in control, fair-minded; facts not adjectives; no urgency devices), how to use tokens, when to add a component, accessibility rules (WCAG 2.2 AA: text contrast ≥ 4.5:1, large text ≥ 3:1, focus visible, targets ≥ 44 px, reduced-motion respected), print rules (letters US Letter, 0.75 in margins, §41.0051 block 14 pt bold untouched), e-mail rules, and the voice rules by pointer to the brief. A contrast table for both themes generated by a script and pasted into the doc.

**C8 Lint.** CI step: fail if any hex colour literal, `rgb(`, or `font-family` appears under `apps/web/src` outside `src/styles/`; fail if `cleanbill/brand.py` is stale against `tokens.css`. One Deno/Node test that loads both theme files and asserts every semantic token resolves.

## Glossary

**ADR** architecture decision record (`docs/adr/`) · **B-nn / O-nn** business decision / open decision in `claude/decisions.md` · **CI** continuous integration — the tests GitHub runs on every push · **Claim code** the random `CB-XXXX-XXXX` credential printed on a letter (ADR 0008) · **Component sheet** the named CSS classes every page is built from · **Contrast ratio** the WCAG measure of text legibility against its background · **Design system** tokens, themes, components, assets, a style guide and a written guide, versioned in the repo · **DNS** the records that point a domain at a server · **Lint** an automated check that fails the build on a rule violation · **Lob / Resend** print-and-mail API / e-mail API · **M8** the copy-review item from the Sep 14 memo · **OFL** SIL Open Font License, under which DM Sans may be vendored · **Open Graph image** the preview picture shown when a link is shared · **PR** pull request · **Primitive / semantic token** a raw value (`--teal`) / a purpose-named alias of it (`--color-primary`) · **QR** the scannable code on the letter · **Ref** Supabase's immutable project identifier · **Selftest** the one-URL end-to-end health check · **Slug** the machine name of a project · **Style guide (living)** a page in the app that renders the design system from its own tokens · **Theme** a file of primitive values that a whole site switches to at once · **Token** a named design value (colour, size, font) read by every component · **WCAG 2.2 AA** the accessibility standard the site meets · **§41.0051** Texas Property Code advertisement-disclosure rule · **308** permanent redirect status.
